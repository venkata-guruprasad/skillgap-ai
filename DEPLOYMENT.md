# SkillGap AI — Production Deployment Guide

This guide provides exact, reproducible production deployment steps for **SkillGap AI** across:
- **Frontend**: **Vercel** (React + Vite + Tailwind CSS static SPA)
- **Backend**: **Render (Docker)** — or **Railway / Fly.io** (recommended alternatives for AI/ML workloads)
- **Database**: **Neon** or **Supabase** (Managed PostgreSQL 16 with TLS)
- **Self-Hosted All-in-One**: **Docker Compose** on a Linux VPS / VM

---

## 1. Production Architecture

```text
[ User Browser (HTTPS) ]
          │
          ▼
[ Vercel CDN — React + Vite SPA ]
  (frontend/vercel.json: SPA rewrites + HSTS/Security Headers)
          │
          │ HTTPS JSON + Multipart PDF/DOCX (<= 5 MB)
          │ Authorization: Bearer <JWT>
          ▼
[ Docker Container — FastAPI + AI/ML Backend ]
  (Render Standard / Railway / Fly.io — >= 2 GB RAM, 1 Uvicorn worker)
  • Baked-in models: spaCy en_core_web_sm, NLTK punkt_tab,
    SentenceTransformers all-MiniLM-L6-v2, career_model_bundle.joblib
  • Startup entrypoint: alembic upgrade head -> uvicorn --proxy-headers
  • Persistent volume: /data/uploads (resume storage)
          │
          │ TLS (?sslmode=require)
          ▼
[ Managed PostgreSQL 16 — Neon or Supabase ]
  • Tables: users, skills, career_roles, resumes, job_descriptions,
    skill_gap_analyses, career_predictions, learning_roadmaps, roadmap_tasks
```

## 2. Hosting Platform Recommendation for AI/ML Workloads

SkillGap AI runs **PyTorch + `sentence-transformers/all-MiniLM-L6-v2` + `spaCy en_core_web_sm` + `Scikit-learn`** inside the FastAPI backend. Peak resident memory is approximately **900 MB – 1.4 GB** with `--workers 1`.

| Platform | Suitability | Minimum Plan | Why |
| --- | --- | --- | --- |
| **Render (Docker)** | Great (Blueprint included: `render.yaml`) | **Standard (2 GB RAM, 1 CPU)** | Render's 512 MB Free/Starter tiers will OOM when loading PyTorch + MiniLM. Standard (2 GB) + Persistent Disk (`/data/uploads`) runs smoothly. |
| **Railway (Docker)** | **Recommended Alternative (Cost-Efficient)** | Hobby / Pro (up to 8 GB RAM, pay-per-use) | Scales smoothly for PyTorch/Sentence-Transformers Docker images with native persistent volumes and zero cold-start sleep. |
| **Fly.io (Docker)** | **Recommended Alternative (Low Latency)** | `shared-cpu-2x` with `2048 MB` RAM | Fast container startup with baked-in HF cache and attached Fly Volumes (`/data/uploads`). |
| **Vercel** | **Recommended for Frontend** | Hobby or Pro | Global CDN, instant preview deploys, automatic HTTPS, and SPA routing via `frontend/vercel.json`. |
| **Neon / Supabase** | **Recommended for PostgreSQL** | Free or Launch / Pro | Managed PostgreSQL 16 with TLS, automated backups, and direct connection strings supported out of the box (SQLAlchemy automatically normalizes `postgres://` -> `postgresql+psycopg2://`). |

## 3. Step-by-Step Cloud Deployment

### Step A — Provision Managed PostgreSQL (Neon or Supabase)

1. **Neon** (`https://neon.tech`) or **Supabase** (`https://supabase.com`):
   - Create a new PostgreSQL 16 database named `skillgap_ai` (or default `neondb`/`postgres`).
   - Copy the **Direct** (non-pooled, or session-pooled) PostgreSQL connection string with SSL enabled:
     ```text
     postgresql://<user>:<password>@<host>/<database>?sslmode=require
     ```
2. **Database Initialization**:
   - You do **not** need to run SQL manually — the backend Docker container's `entrypoint.sh` automatically runs `alembic upgrade head` (`0001` -> `0005`) on startup and FastAPI seeds the 8 labeled sample job descriptions idempotently.
   - To run migrations manually from your workstation instead:
     ```bash
     cd skillgap-ai/backend
     export DATABASE_URL="postgresql://<user>:<password>@<host>/<database>?sslmode=require"
     alembic upgrade head
     ```

---

### Step B — Deploy Backend (Render or Railway)

#### Option 1: Render (via `render.yaml` Blueprint)
1. Push the repository to GitHub (confirm `.env`, `*.db`, and `data/uploads/` are excluded via `.gitignore`).
2. In Render Dashboard -> **New +** -> **Blueprint** -> select your repository (root directory `skillgap-ai`, using `render.yaml`).
3. Set the prompted secret environment variables in Render Dashboard:
   - `DATABASE_URL`: Your Neon or Supabase URI ending in `?sslmode=require`
   - `CORS_ORIGINS`: Your Vercel frontend URL (e.g., `https://skillgap-ai.vercel.app`) — update this immediately after Step C if needed.
   - `SECRET_KEY`: Auto-generated by Render (`generateValue: true`), or generate via:
     ```bash
     python -c "import secrets; print(secrets.token_urlsafe(48))"
     ```
   - *(Optional)* `LLM_PROVIDER` (`openai` or `gemini`) and `LLM_API_KEY` if you want LLM-enhanced roadmaps instead of the built-in deterministic engine.
4. Click **Apply**. During build, `backend/Dockerfile` bakes `en_core_web_sm`, `punkt_tab`, `all-MiniLM-L6-v2`, and `career_model_bundle.joblib` into the image so cold starts never download models at runtime.
5. Verify health after deploy:
   ```bash
   curl https://<your-backend>.onrender.com/api/health
   curl https://<your-backend>.onrender.com/api/health/db
   ```

#### Option 2: Railway (Docker Alternative)
1. In Railway -> **New Project** -> **Deploy from GitHub Repo**.
2. Set **Root Directory** to `skillgap-ai/backend` (Railway automatically detects `backend/Dockerfile`).
3. Attach a **Volume** mounted at `/data/uploads`.
4. Add the exact Backend Environment Variables from Section 4 below, and generate a public domain under **Settings -> Networking**.

---

### Step C — Deploy Frontend (Vercel)

1. In Vercel Dashboard -> **Add New Project** -> import your GitHub repository.
2. Configure Build Settings:
   - **Root Directory**: `frontend`
   - **Framework Preset**: `Vite` (auto-detected via `frontend/vercel.json`)
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
3. Add **Environment Variables** in Vercel:
   - `VITE_API_BASE_URL` = `https://<your-backend>.onrender.com` *(no trailing slash)*
   - `VITE_APP_NAME` = `SkillGap AI`
4. Click **Deploy**.
5. Copy your live Vercel URL (e.g., `https://skillgap-ai.vercel.app`) and set it as `CORS_ORIGINS` on your backend service, then restart/redeploy the backend.

---

### Step D — Self-Hosted Production Deployment (Docker Compose)

For deploying all 3 containers (`db`, `backend`, `frontend`) together on a Linux VM (2+ vCPU, 4 GB RAM recommended):

```bash
cd skillgap-ai
cp .env.example .env
```

Edit `.env` for production:
- Set `APP_ENV=production`, `DEBUG=false`, `ENABLE_API_DOCS=false`
- Set strong `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`
- Set a strong 48+ char `SECRET_KEY`
- Set `CORS_ORIGINS` and `VITE_API_BASE_URL` to your domain (or `http://<server-ip>:5173` / `http://<server-ip>:8000`)

Build and start:
```bash
docker compose up --build -d
docker compose ps
docker compose logs -f backend
```

## 4. Required Environment Variables Reference

### Backend Service (Render / Railway / Docker)

| Variable | Required | Production Value / Example | Notes |
| --- | --- | --- | --- |
| `APP_ENV` | Yes | `production` | Enforces `DEBUG=false`, strong JWT secret, PostgreSQL, HSTS, and disables dev demo seeding. |
| `DEBUG` | Yes | `false` | Automatically forced to `false` when `APP_ENV=production`. |
| `ENABLE_API_DOCS` | No | `false` | Set `true` only if you want public `/docs` Swagger UI in production. |
| `DATABASE_URL` | Yes* | `postgresql://user:pass@host/db?sslmode=require` | Neon/Supabase URI (`postgres://` is auto-normalized to `postgresql+psycopg2://`). *Or set `POSTGRES_HOST/PORT/USER/PASSWORD/DB`. |
| `SECRET_KEY` | Yes | `<48+ char random string>` | Startup fails fast if `< 32` chars or placeholder text in production. |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | No | `120` | JWT expiration window in minutes. |
| `CORS_ORIGINS` | Yes | `https://skillgap-ai.vercel.app` | Comma-separated exact frontend origins; `*` is blocked in production. |
| `UPLOAD_DIR` | No | `/data/uploads` | Point to a persistent disk/volume. |
| `UVICORN_WORKERS` | No | `1` | Keep `1` on 2 GB RAM instances so ML models aren't duplicated across workers. |
| `LLM_PROVIDER` | No | `none` / `openai` / `gemini` | Leave `none` for zero-cost deterministic curated roadmaps. |
| `LLM_API_KEY` | Conditional | *(secret)* | Required only when `LLM_PROVIDER` is `openai` or `gemini`. Never exposed to clients. |
| `LLM_MODEL` | No | `gpt-4o-mini` / `gemini-2.0-flash` | Optional model override. |

### Frontend Service (Vercel / Docker Build Args)

| Variable | Required | Production Value / Example |
| --- | --- | --- |
| `VITE_API_BASE_URL` | Yes | `https://skillgap-ai-backend.onrender.com` |
| `VITE_APP_NAME` | No | `SkillGap AI` |

## 5. Post-Deployment Verification Checklist

After deploying, run these checks against your live URLs:

1. **API & DB Health**:
   ```bash
   curl -i https://<backend-domain>/api/health
   curl -i https://<backend-domain>/api/health/db
   ```
   Confirm `200 OK`, `"status": "success"`, `"PostgreSQL connection successful"`, and presence of `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, and `Strict-Transport-Security`.
2. **Frontend SPA Routing**: Open `https://<frontend-domain>/dashboard` directly in a fresh browser tab and confirm Vercel rewrites cleanly to the app (no 404).
3. **Full End-to-End Smoke Test**:
   - Register a new account -> Sign out -> Log back in
   - Upload a PDF or DOCX resume (<= 5 MB) -> Confirm NLP skill extraction
   - Run Skill Gap Analysis against a seeded job description
   - Run 12-role ML Career Prediction
   - Generate a 30-day Learning Roadmap -> Check off a task -> Hard-reload -> Confirm progress persists in PostgreSQL & appears on `/dashboard`.

## 6. Troubleshooting Guide

- **Backend OOM (Exit Code 137) on Render/Fly**: Increase container memory to at least **2 GB RAM** and keep `UVICORN_WORKERS=1`. PyTorch + MiniLM + spaCy exceed 512 MB.
- **CORS Blocked in Browser**: Verify `CORS_ORIGINS` matches your Vercel URL **exactly** (including `https://`, no trailing slash) and redeploy the backend.
- **Startup fails with `RuntimeError: Production SECRET_KEY...`**: Generate a random 48+ char secret (`python -c "import secrets; print(secrets.token_urlsafe(48))"`) and replace any placeholder value.
- **PostgreSQL SSL Error on Neon/Supabase**: Append `?sslmode=require` to `DATABASE_URL`.
- **413 Payload Too Large on Resume Upload**: In self-hosted Nginx, `frontend/nginx.conf` sets `client_max_body_size 6m;`. If fronting with an external reverse proxy/load balancer, ensure its max request body size is at least 6 MB.
- **Alembic `DuplicateTable` error on fresh PostgreSQL**: Do not pre-apply `database/schema.sql` if using `entrypoint.sh` (`alembic upgrade head`). Use either Alembic migrations (default in Docker/cloud) OR manual `schema.sql` + `alembic stamp head`.
